# 情绪诱发范式（PsychoPy）

该程序按 `范式设置.png` 搭建六套可运行流程；当前正式整合实验先启用范式1–3，范式4–6保留但暂不进入整合流程：

| 范式 | 材料 | Trial 数 | 单个 Trial |
|---|---|---:|---|
| 1 | 视频 | 6（正/中/负=2/2/2） | 注视 5 s → 完整视频 → 1–9 评分并空格确认 → 休息 12 s |
| 2 | 人脸图片 | 30（正/中/负=10/10/10） | 注视 5 s → 图片 2 s → 1–9 评分并空格确认 |
| 3 | 综合图片 | 20（正/中/负=7/6/7） | 注视 5 s → 图片 5 s → 1–9 评分并空格确认 |

正式运行默认为一个整合实验，一次启动连续完成范式1–3，不需要每个范式重新启动，共56个素材。程序读取视频真实时长并按类别配额筛选材料，使计划时长接近30分钟；区块间被试可自行休息，因此实际总耗时还取决于评分速度和区块休息。预计评分按每次8秒计入。范式4–6的配置和单范式调试功能仍保留，后续可重新启用。

同一被试后续 session 会读取 `data/` 中已有的刺激计划，优先选择未使用材料；某一类别的剩余材料不足时才会复用，以保证情绪类别平衡。三个区块始终按范式1（视频）→范式2（人脸图片）→范式3（综合图片）的顺序运行；各区块内部素材顺序仍随机。最终顺序、预计时长、是否复用和随机种子都会在实验开始前保存，因此可复现。评分界面中黄色指针默认位于 5，使用 `←/→`（也支持 A/D）移动，空格或回车确认；数字 1–9 可直接定位。指针不移动时可直接确认评分 5。正式版固定时长阶段不接受空格跳过；`Esc` 始终作为安全中止键。

双击 `启动流程演示版.bat` 可运行流程演示：一次连续展示范式1–3，并使用与正式版完全相同的素材数量和类别配额；演示版仅缩短注视、图片、视频和休息阶段，素材呈现期间可按空格跳过。该快捷方式默认只写本地日志，不向打标盒或 LSL 发marker；演示版不用于正式采集。

双击 `启动单范式评分打标测试.bat` 可运行两个trial的评分硬件打标测试。脚本会自动识别WCH CH343/CH9102打标盒串口，然后以 `serial` marker启动窗口化范式2短测；最终确认评分时发送marker 41–49。

## 运行

推荐直接双击 `启动范式.bat`。脚本会优先调用 `C:\Program Files\PsychoPy\python.exe`；也可在 PsychoPy Standalone 的 Coder 中打开 `emotion_paradigm.py` 后运行，或执行：

```powershell
& "C:\Program Files\PsychoPy\python.exe" emotion_paradigm.py
```

启动窗口中填写被试编号、场次和打标方式，保持默认的“整合实验（推荐，范式1–3，自动约30分钟）”即可。下方单范式选择只用于调试。正式实验使用全屏；首次检查可勾选“工程短测（减少素材并缩短时长）”并取消全屏。单范式工程短测只取2个材料；整合工程短测每个区块各取3个材料（正/中/负各1个），固定画面缩短到0.3–0.5秒，视频最多播放3秒。

### 面部摄像头录像

主启动窗口默认勾选“摄像头录像”，可设置摄像头编号、分辨率和请求帧率。程序先实测摄像头帧率，再显示实时镜像取景；确认被试面部完整、清晰且光线均匀后按空格进入范式。录像从取景检查开始，覆盖开始提示、全部区块和结束画面；摄像头打不开、持续读帧失败或实测帧率低于 `config.json` 中的最低值时，实验会停止并报错。

默认请求 `1280×720 @ 60fps`、MJPG编码，但实际能力由摄像头、USB接口和曝光决定。取景页会显示实测帧率；微表情正式采集不能只看驱动报告值，应根据研究方案确认实际帧率、曝光、照明和存储空间。程序默认要求录像盘至少剩余40GB，并在 `*_face_info.json` 中估算每小时占用；MJPG便于逐帧读取但文件较大。标准USB摄像头通常没有可用于与Blackrock精确对齐的曝光硬件时间戳，因此程序保存的逐帧时间是电脑收到帧的时间；精确同步仍以Blackrock硬件marker为主，若需要逐帧硬件级对齐，应使用带触发/时间戳的工业相机，或把由打标盒驱动的LED放入相机视野。

无需 PsychoPy 即可先检查素材和随机抽样：

```powershell
python emotion_paradigm.py --self-test
```

无人值守的窗口化验收可使用（会自动开始并选择评分 5）：

```powershell
& "C:\Program Files\PsychoPy\python.exe" emotion_paradigm.py --no-gui --integrated --windowed --test --smoke-test
```

## 打标

事件均与刺激画面第一次 `win.flip()` 同步安排。默认 `log` 只写 marker 日志，适合无硬件试跑。正式采集可在启动窗口选择：

- `parallel`：并口，地址填 `0x0378`（按实际设备修改）；输出 10 ms TTL 脉冲后归零。
- `serial`：串口，端口填 `COM3` 等；默认 115200、8N1，并按旧 ESP32-S3 打标盒协议发送两字节帧 `[0x36, marker]`，不额外发送零字节。
- `lsl`：创建名为 `EmotionParadigmMarkers` 的 int32 LSL 流；端口栏留空。
- `parallel+lsl`：同一次翻屏先输出并口 marker，再推送同值 LSL marker。
- `serial+lsl`：同一次翻屏先输出串口 marker，再推送同值 LSL marker。

串口协议、波特率、是否发送零字节、脉宽、LSL 流名可在 `config.json` 修改。旧打标盒使用 `serial_protocol: "esp32_header"` 和十进制帧头 `54`（即 `0x36`）；若以后直接连接只收单字节的设备，可改为 `serial_protocol: "raw_byte"`。并口和 `win.callOnFlip` 的用法与当前 PsychoPy API 一致：[ParallelPort 文档](https://devdocs.psychopy.org/api/parallel.html)、[Window.callOnFlip 文档](https://devdocs.psychopy.org/api/visual/window.html#psychopy.visual.Window.callOnFlip)。

### Blackrock 建议接法

如果打标盒能够把 LSL marker 转换成 TTL/串口事件，选择 `lsl`；如果打标盒本身通过 USB 串口连接范式电脑，且同时把事件送入 Blackrock，选择 `serial+lsl`。若是并口/TTL 触发盒则选择 `parallel+lsl`。LSL 只作为网络流时不会自动写入 Blackrock 的 NSx/NEV 文件，必须由打标盒、Blackrock 数字输入或采集桥接程序接收。

Blackrock NeuroPort 的数字输入是带 strobe 的 16-bit、0–5 V TTL 接口；串口输入为 RS-232 115200、8数据位、无校验、1停止位。正式接线前必须核对打标盒输出电平、strobe/数据线和串口协议，不能把 USB-TTL 电平直接当作 RS-232 接入。

当前目录中的旧 ESP32-S3 固件表明：串口接收 `[0x36, marker]` 后，marker 的 bit0–bit7 分别输出到 GPIO2–GPIO9；GPIO10 为使能/strobe，空闲为高，输出时先拉低 1 ms、再拉高，数据保持 1 ms 后清零。也就是说，原眼动仪只是这个串口帧的发送方，新 PsychoPy 范式可以直接替代它。连接盒子后先双击 `检测打标盒串口.bat` 查看 COM 口，再执行 `trigger_box_test.py --port COM号` 向采集端发送逐位诊断序列。

在另一台装有 Python/PsychoPy 与 pylsl 的电脑上运行 `lsl_marker_monitor.py`，或双击 `启动LSL监听.bat`，可查看范式发出的每一个 LSL 编码。这只能验证 LSL 网络链路；最终仍需在 Blackrock 生成的事件文件/数字输入通道中核对相同编码和顺序。

### Marker 编码

| 编码 | 含义 |
|---:|---|
| 1 | 实验开始 |
| 10 | 注视开始 |
| 21 / 22 / 23 / 24 | 中性 / 正性 / 负性 / 未分类材料开始 |
| 30 | 评分界面开始 |
| 41–49 | 确认最终评分 1–9 |
| 50 | 休息开始 |
| 60 | Trial 结束 |
| 99 | 实验结束 |
| 101–106 | 范式1–6区块开始 |
| 111–116 | 范式1–6区块结束 |
| 255 | `Esc` 中止 |

如采集系统需要另一套编码，可直接修改 `config.json` 的 `marker_codes`，无需改程序。

## 数据

数据保存在 `data/`，整合实验文件名使用 `pALL`，并在一个文件中保留当前范式1–3的三个区块：

- `*_stimulus_plan.csv`：区块顺序、全局trial编号、预计时长、材料及是否跨session复用。
- `*_events.csv`：所有实验、区块和trial marker的编码及程序时钟时间。
- `*_trials.csv`：全部区块的实际翻屏时间、评分、反应时和完成状态。
- `*_face.avi`：覆盖本次采集过程的面部视频。
- `*_face_frames.csv`：每个写入视频帧的帧号、与范式事件同源的电脑时钟和墙钟时间。
- `*_face_info.json`：摄像头编号、分辨率、请求/驱动报告/校准/全程实测帧率、帧数及错误状态。
- `video_durations.json`：ffprobe生成的视频时长缓存；素材变化后会自动刷新对应条目。

CSV 使用 UTF-8 BOM，可直接用中文 Excel 打开。正式采集前请使用与实验相同的电脑、显示器和打标硬件完成一次全流程测试，并用采集端确认 TTL/串口/LSL 编码和时序。
